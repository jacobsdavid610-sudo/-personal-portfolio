# gitstats.sh

Summarizes commit counts per author in a git repository. Answers "who's
actually been committing here, and how much" without reaching for `gh` or a
web UI — just `git log` piped through standard coreutils.

## Why

Useful for a quick gut-check on a repo you've just cloned: who are the main
contributors, is activity concentrated in one person, has anyone committed
recently (`--since`). No dependencies beyond `git`, `sort`, `uniq`, `awk` —
works anywhere git works.

## Usage

```
gitstats.sh [repo-dir] [--since DATE] [--top N]
```

- `repo-dir` — path to the repository to analyze. Defaults to `.` (current
  directory) if omitted.
- `--since DATE` — only count commits since `DATE`. Accepts anything
  `git log --since` accepts (`"2 weeks ago"`, `"2026-01-01"`, etc.).
- `--top N` — only show the top `N` authors by commit count.

## Example

Against a real 5-commit repo (Ada: 3 commits, Grace: 2):

```
$ gitstats.sh /tmp/demo_repo
     3  Ada
     2  Grace

Total: 5 commit(s) shown.
```

With `--top 1`, only Ada is shown, and the total reflects just the shown
subset (it's a "total of what's printed," not a repo-wide total when `--top`
truncates the list):

```
$ gitstats.sh /tmp/demo_repo --top 1
     3  Ada

Total: 3 commit(s) shown.
```

## Exit codes

- `0` — ran successfully (including the "no commits found" case).
- `1` — the given directory isn't a git repository (no `.git` found).

## Design notes

- Counts by `%an` (author name as recorded in the commit, not `git blame`
  line ownership) — this is "who committed," not "who wrote the most code."
  Someone who commits a big autogenerated file will outrank someone who made
  ten careful small commits; that's expected for this kind of tool, not a
  bug.
- No merge/no-merge distinction — merge commits count too, same as plain
  `git log` would show them.

## Running the tests

```
bash tests/test_gitstats.sh
```

The test suite builds a real scratch git repo with `--allow-empty` commits
from two different authors (so it needs no source files, just fast local git
operations) and asserts against `gitstats.sh`'s actual output — no mocking
of `git` itself.
